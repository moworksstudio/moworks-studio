# Sound: a code-made kit, on key moments only

Every effect is **generated by code**: `tools/sfx/build_sounds.py` synthesises them (numpy + scipy) with fixed seeds,
so every run writes the same files. No samples, no downloads, no licences: the sounds belong to whoever runs the code.
You **can't hear**: report the measured loudness and ask the user to listen.

```bash
uv run --with numpy --with scipy python tools/sfx/build_sounds.py                                  # (re)build public/sfx/kit/ + INDEX.md
uv run --with numpy --with scipy python tools/sfx/build_sounds.py --audition out/kit-audition.wav  # all sounds in a row, for the user
```

## The kit (`public/sfx/kit/`) and the moment each one belongs to
| Toon moment | Sound | Gain under a voice (dB) |
|---|---|---|
| A physical hit that IS the beat (a kick, a door landing, a fall, a wheel slamming down) | `impact` | −9…−8 |
| Something goes wrong (a burn shows, an ankle rolls, a machine dies) | `blip-down` or `glitch` | −8…−6 |
| A win that helps someone (pouring for the team, a rescue lands) | `win` | −8…−7 |
| A verdict object (an X-ray crack, a diagnosis card, a scoreboard, a label) | `chip` | −5…−4 |
| One small key action (a jab, a switch, a hammer tap, a step) | `tick` | −5…−3 |
| Many things land, or a counter runs | `count` | −7…−6 |
| The power switches on, an object transforms, a value locks in | `lock` or `blip-up` | −8…−6 |
| Something is cut in half | `slice` | −8…−6 |
| Two things square off, a hard metallic stop | `vs` | −9…−8 |
| A button or an in-world screen is pressed | `click` | −8…−5 |
| The end card / the final still | `resolve` | −9…−7 |

The gains are relative to the files' designed levels. Start there and adjust ±3 dB.

## Rules
1. **Key moments only:** about **one cue per 3–4 s at most**, ≤ 3–4 per scene, ≥ 0.5 s apart. Shorts: 3–5 per
   short. Long chapters breathe: about one per 6–10 s.
2. **Silent on purpose:** captions, in-world text and titles, cuts, camera moves, dialogue lines, and every item after
   the first in a row of similar things.
3. **Never** a whoosh, swoosh, swish, whip, riser or vine-boom. A cut stays clean; a moment lands with a cue from the
   table instead.
4. Put the cue **on the visual hit** (the frame where the thing happens), not where the element first appears.
5. **Keep words clear:** prefer the voice's pauses (`voice.words.json → silences`); a hit that must land on a word goes
   3–6 dB lower; effects near speech get short tails.
6. "Remove that sound" means remove exactly that one cue.

## In the composition
```ts
// vo.ts
export const SFX: { n: string; t: number; g: number }[] = [
  { n: "impact", t: 1.05, g: -9 }, // the kick lands
  { n: "win", t: 27.84, g: -8 },   // the last mug fills on "barehanded"
];
```
`Video.tsx → SOUND` hands the voice and the cues to `tools/render.mjs`, which mixes them (`tools/sfx/mix.py`):
- **with a voice:** voice + effects are mastered to **−14 LUFS integrated** (one static gain, a 4×-oversampled limiter,
  true peak ≤ −1.5 dBTP);
- **without a voice:** the effects stay at their designed level (they're made to sit under a voice in an editor), and
  a `<CompId>.sfx.wav` is written beside the MP4. For a standalone picture + effects video, set `master: true` in
  `SOUND`.

Report it like this: "6 cues · −14.0 LUFS, true peak −2.0 dBTP (measured; I can't listen, so please check by ear)".

## Music (only when the user asks)
No music ships with the kit. When the user asks for music and `modules.music` is on, compose it in code with the
original-music skill; it plays under the voice through `SOUND.music` with volume keys. Never download music or imitate
a known song.

## Designing a new sound (when the user wants one the kit doesn't have)
Add a builder to `tools/sfx/build_sounds.py` from its ingredients (`osc`, `fm`, `bell`, `sub_kick`, `bp`/`lp`/`hp`,
`click`, `space`…), add a `SOUNDS` row (builder, loudness target, use), re-run it, and add the sound to the table
above. A sound timed to one video only goes in its own `tools/sfx/build_<slug>.py` (it can import
`tools/sfx/sfxlib.py`) writing to `public/sfx/<slug>/`; point that video's `sfxDir` there. Never build the whoosh
family (a smooth noise sweep that rises or falls) unless the user asks for it.
